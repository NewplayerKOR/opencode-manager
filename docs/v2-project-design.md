# v2-project-design.md — V2 프로젝트 단위 정리 설계 (설계만, 코드 없음)

> 작성일: 2026-10-09 / 상태: v1 초안 / 전제: T12 요구(V2-R04), T13 안전장치(S01–S05), T14 세션 cascade 재사용
> 범위: 프로젝트 통째 1건 단위. 본 문서는 설계이며 V1 앱·`src/` 변경 없음.

## 1. 보관 (V2-R03 대응)
- 소속 세션 전건에 `session.time_archived` 기록 (T14 §1 재사용). `project`·`project_directory` 행은 유지.
- 복원은 소속 세션 전건 NULL 환원. S04 2단계 확인 적용.

## 2. 삭제 순서 (V2-R04 대응)
1. 소속 세션 전건에 T14 §2 cascade 적용 (part→message→todo·session_*→event→session)
2. `project_directory` 해당 행 제거
3. `project` 본 행 제거
4. 관련 `session_diff` 파일 일괄 OS 휴지통 이동 (stem==소속 세션 id)
5. 삭제 후 검증: 소속 세션 id·`project_id` 잔류 0건
- `global` 프로젝트(T02 인계, 공유 세션 2건)는 정리 대상에서 제외. 대상 선택 목록에 노출하지 않음.

## 3. `workspace.*.dat` 방침: 파일째 휴지통
- 매핑되는 workspace 파일은 통째로 OS 휴지통 이동 (S03). 키 단위 편집·재빌드 미수행.
- 기각된 대안: `.dat` 재빌드 — Desktop 실행 중 재생성되므로 충돌 위험, T12 §4 미포함 유지와 정합.
- `global.dat` 본문은 수정하지 않음. 목록 불일치는 Desktop 재시작 시 해소 전제로 안내 문구 표시.

## 4. 활성 보호: 추가 확인 (차단 아님)
- 대상이 `global.dat` 활성 목록에 있으면 S04 2단계에 활성 경고 1단계 추가 (총 3단계 확인) 후 허용.
- 경고 문구: "Desktop에서 보이는 활성 프로젝트입니다. 통째 정리하면 목록에서 사라집니다. 계속합니까."
- 비활성 프로젝트는 S04 2단계 그대로.

## 5. T13 게이트 적용
- `docs/v2-safety.md` §2 흐름 전제. S01 미통과(Desktop 실행 중) 시 삭제 경로 차단, 보관만 가능.
- S02 백업은 프로젝트 단위 일괄분 (소속 세션 rows + diff 일괄 + 매핑 workspace 파일 목록).

## 6. 활성 오삭제 방지 대조
- 조건 ①: `global` 프로젝트 정리 대상 제외 (§2) — 공유 세션 보호.
- 조건 ②: 활성 대상 3단계 확인 (§4) — 클릭 실수 방지.
- 조건 ③: S01 Desktop 종료 확인 (§5) — 실행 중 변경 방지.
- ①–③ 모두 명시됨. T16 복원 설계와 연계.
