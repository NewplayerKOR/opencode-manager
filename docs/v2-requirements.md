# v2-requirements.md — V2 요구사항 정의 (목록만, 설계 아님)

> 작성일: 2026-10-06 / 상태: v1 초안 / 전제: V1 읽기전용 뷰어 완료(T11 DONE) 후 착수
> 범위 확정 (2026-09-26): 세션 단위 + 프로젝트 단위(통째) 모두 포함. 구체 설계는 T13–T16에서 수행, 본 문서는 목록 정의까지만.

## 1. 용어 정의
- 보관: 숨김 + 복원 가능 상태. 목록에서 가려지나 데이터는 유지되며 되돌릴 수 있음.
- 삭제: 사용자가 직접 확정한 제거. 보관과 별개 선택지로 제공.
- 본 문서의 "삭제/보관"은 V2 요구 범위 기술이며, V1 앱에는 해당 동작이 없음.

## 2. 포함 요구사항
| ID | 요구 | 범위 |
|---|---|---|
| V2-R01 | 세션 단위 보관 | 숨김 + 복원 가능. 목록·집계에서 제외 표시 |
| V2-R02 | 세션 단위 삭제 | 사용자 확정 시 제거. 연계 범위(DB 세션·메시지, `session_diff` 파일, `.dat` 매핑)는 T14에서 확정 |
| V2-R03 | 프로젝트 단위 보관 | 통째 숨김 + 복원 가능 |
| V2-R04 | 프로젝트 단위 삭제(통째 정리) | 사용자 확정 시 소속 세션 일괄 처리. `workspace.*.dat` 처리 방침은 T15에서 확정 |
| V2-R05 | F04 진단 연계 | R01–R05 의심 표시를 보관/삭제 판단 재료로 노출 (판정 자체는 V1과 동일) |

## 3. 제외 요구사항 (확정)
| 항목 | 사유 |
|---|---|
| lockfile 삭제 | 실행 중 잠금과 잔류 구분 불가, 데이터 손실 위험 |
| 프로세스 kill | 강제 종료 시 DB·WAL 정합 깨짐 위험 |
| 자동 정리 | 사용자 확인 없는 제거 금지 원칙과 충돌 |

## 4. `FEATURES.md` §5 Non-Goal 정합 대조
- §5의 "삭제, 보관, 이동, `.dat` 재빌드, 자동 정리, lockfile 삭제, 프로세스 kill"은 V1(1단계) 범위 밖이라는 정의이며, V2에서 이를 요구사항으로 올리는 것과 충돌하지 않음.
- 단, 위 제외 3종은 V2에서도 범위 밖을 유지한다 (본 문서 §3 확정).
- "이동", "`.dat` 재빌드"는 V2-R02·V2-R04의 연계 처리(T14·T15)에서 방침 확정 시 재논의. 본 문서에서는 미포함.
