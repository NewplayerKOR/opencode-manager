# v2-backup-design.md — V2 백업/복원 설계 (설계만, 코드 없음)

> 작성일: 2026-10-10 / 상태: v1 초안 / 전제: T13 안전장치(S02·S05), T14·T15 백업 연계분
> 원칙: 대상별 최소 백업, 백업본 검증 전 삭제 실행 불가. 본 문서는 설계이며 V1 앱·`src/` 변경 없음.

## 1. 백업 포맷: 폴더 그대로
- 구조 (삭제 실행 전 생성, S02):
  - `manifest.json` — 백업 시각·사유·대상 종류(세션/프로젝트)·id 목록·S04 확정 기록
  - `db/` — 대상 rows 추출분 (세션: T14 §2 cascade 집합, 프로젝트: T15 §2 일괄 집합)
  - `session_diff/` — 해당 `ses_*.json` 원본 그대로
  - `dat/` — 관련 `.dat` 복사본 (T15는 매핑 workspace 파일, T14는 불일치 기록분)
- 원본 구조 유지이므로 육안 확인 가능. 압축 미수행 (체크섬 대조 단순화).

## 2. 복원 절차
1. Desktop 종료 확인 (S01, 복원 시에도 동일)
2. 휴지통 이동분 원위치 (OS 휴지통 복원)
3. 백업본 DB rows 재삽입 (삭제 역순: session → event → todo·session_* → message → part)
4. 보관분은 `session.time_archived` NULL 환원
5. `.dat`는 복원 대상 밖 (Desktop이 재생성, T15 §3과 정합)

## 3. 복원 검증: 체크섬 대조
- 파일: 백업 시 기록한 SHA-256과 복원 후 대조. 불일치 시 복원 실패 판정·재시도 안내.
- DB: 삭제 전 id 목록(manifest)과 복원 후 `COUNT`·id 집합 대조. 고아 row 0건 조건 (T14 §6 재사용).
- 검증 통과 전에는 완료 처리 불가. 실패 내역은 화면 안내 문구로 표시.

## 4. 복원 가능 대조 (T14·T15 × 본 설계)
| 삭제 범위 | 백업 커버 | 복원 경로 | 검증 |
|---|---|---|---|
| 세션 1건 (T14) | rows 추출분+diff+불일치 기록 | §2 절차 (역순 재삽입) | 체크섬+id 집합 |
| 프로젝트 통째 (T15) | 일괄 rows+diff 일괄+workspace 파일 목록 | §2 절차 (프로젝트행 포함) | 체크섬+id 집합 |
| 보관분 | 원본 유지 | NULL 환원 | 건수 대조 |

- V2 설계 블록(T12–T16) 완료. V2 구현(T17 이후)은 별도 세분화 대상.
